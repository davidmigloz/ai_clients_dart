# Claude SDK provider and helper boundaries

The two pinned SDKs expose six cloud adapters outside the Anthropic core HTTP surface. Python implements them in optional libraries in `anthropic`. TypeScript splits them into `aws-sdk`, `bedrock-sdk`, `google-cloud-sdk`, `vertex-sdk`, and `foundry-sdk`. Dart currently exposes only the generic Anthropic client, its base URL/header/transport configuration, and its API-key credential provider. The monorepo's `googleai_dart` supports Gemini with Google API and Vertex AI backends. The deprecated `vertex_ai` package covers Google's earlier generative APIs and vector search. Neither provides Claude routes, credential wiring, or Claude event parsing. [Pinned Python provider source](https://github.com/anthropics/anthropic-sdk-python/tree/5139cf2e7d07aa618a6c30b7e0c712f10ccb5ad9/src/anthropic/lib) · [Pinned TypeScript packages](https://github.com/anthropics/anthropic-sdk-typescript/tree/590783078cd961a0df698d9fddc0275c65ff3afd/packages)

| Provider | Public wire behavior | Dart alignment |
| --- | --- | --- |
| Claude Platform on AWS | `https://aws-external-anthropic.{region}.api.aws/v1/…` with standard Claude wire format. Sign with SigV4 service `aws-external-anthropic` or use AWS-issued Bearer key. Resource requests require `anthropic-workspace-id`; Admin requests omit the requirement. Most first-party routes work, with limited Admin, Activity Feed via IAM, and Managed Agents differences. | Standard routes can be documented and exercised with an injected Bearer key and workspace. SDK parity includes AWS credential chain/signing and scoping. |
| Amazon Bedrock Mantle | `https://bedrock-mantle.{region}.api.aws/anthropic/v1/messages` and count tokens, native SSE and standard Claude body/header. AWS Bedrock Bearer token or SigV4. No Files, Models, Batches, Admin, Compliance, or Managed Agents. | Standard client can implement static Bearer usage with base prefix intact. SDK parity includes signed requests, region resolution, accepted-route restriction, Bedrock query/model rules, and provider request-ID metadata. |
| Amazon Bedrock Runtime | `https://bedrock-runtime.{region}.amazonaws.com/model/{model}/invoke` or `invoke-with-response-stream`, with Bearer token or SigV4. Separate count-tokens route; AWS eventstream frames wrap Claude payloads. SDK moves API version to `anthropic_version` in JSON and moves model into path. No Batches, Models, Admin, Compliance, or Managed Agents. | Add a dedicated adapter slice. Passing a different base URL alone leaves the protocol mismatched. Preserve ARN/profile IDs and the pinned SDK model-ID path treatment. |
| Google Cloud, Google managed (Vertex) | `aiplatform.googleapis.com/v1/projects/{project}/locations/{region}/publishers/anthropic/models/{model}:rawPredict`, or `:streamRawPredict` and separate `count-tokens:rawPredict`. ADC Bearer with cloud-platform scope. SDK rewrites path and puts `anthropic_version` in JSON. Core inference, no Batches, Models, Admin, Compliance, or Managed Agents. | Dedicated Claude Vertex adapter. Test project/location/model encoding, supported regional hosts, stream path, count-tokens wrapper and auth; Gemini coverage elsewhere does not exercise this protocol. |
| Google Cloud, Anthropic managed | `https://claude.googleapis.com/v1/projects/{project}/locations/{location}/workspaces/{workspace}/invoke/v1/…`, or organization root `…/claudeOrganization/invoke/v1/…`. ADC Bearer; default location `global`. Current SDK routes organization-scoped and user-profile requests without a workspace. Uses standard Claude body/SSE, with selective feature availability. | Document explicit routing and token configuration. Adapter scope includes deriving and validating roots, using correct org/workspace route, Google ADC and asynchronous token refresh, retaining custom base URL. |
| Microsoft Foundry | `https://{resource}.services.ai.azure.com/anthropic/v1/…`; uses `x-api-key` or Entra Bearer. No Admin, Compliance, Managed Agents, Models, Batches or User Profiles. Azure-hosted deployments omit Files, Skills, code execution, programmatic tool calling and newer web-tool versions; Anthropic-hosted deployments support those. | Document base URL+auth for compatible routes; SDK parity includes configurable resource or base URL, Entra provider, and preserving both `request-id` and `apim-request-id`. |

SDK v2's 2026-10-21 version applies to the provider paths as well. Bedrock models 4.6 or older still require their previously supported API version. Bedrock Runtime and Vertex place the version in the body; the native HTTP adapters use `anthropic-version`. Test old and current values through each supported backend. Never infer provider support by accepting a first-party schema alone. Verify first-party default and custom base URL/beta/auth overrides before adding adapter-specific behavior. ## Suggested acceptance

- For native-wire provider configuration, demonstrate the proper hostname/path prefix, expected auth and version headers, omitted first-party secrets/unsupported headers, provider feature limits, and deterministic request fixtures. A bespoke signing/credential chain can be handled in separate reviewable adapter PRs.
- For Bedrock Runtime and Google-managed Vertex, require public methods that perform a non-streamed Messages call, streaming, and token counting where supported through the provider's pinned wire translation. Exercise provider error envelopes, response request IDs, unknown SSE/eventstream events, abort and credential refresh without live calls. Test empty/dot segments and model IDs with ARN/inference-profile punctuation; sign the final method, URI and body rather than an intermediate shape.
- For OAuth/WIF, distinguish static bearer from provider-based credentials. JWT exchange at `POST /v1/oauth/token` uses `oauth-2025-04-20,oidc-federation-2026-04-01`, JSON RFC7523 fields, no Claude API key or API version, and a short-lived response. Refresh grants and token-cache-authenticated requests use only the OAuth flag, appended to existing feature flags on API requests. Assert test renewal, concurrency, expiry, retry/backoff, token redaction, rejected credential combinations, and mixed workspace/organization routes. [WIF reference](https://platform.claude.com/docs/en/manage-claude/wif-reference)

## SDK helpers and other products

- Dart already offers raw streamed message events and accumulation, middleware-style interceptors, beta header values, and JSON schemas for tools. Official SDKs also offer typed structured-output parse and strict-schema normalization, iterable pagination, typed SSE convenience streams, tool runner, computer/browser callbacks and policy checks, local memory/file/skill and MCP helpers, Managed Agents session runners and self-hosted worker lifecycle, webhook signature validation, and opt-in OpenTelemetry. Record each helper as SDK convenience parity with its own acceptance tests if implemented. Distinguish core endpoint contracts from local application runtimes and avoid describing the existing Dart models as equivalent to the execution helpers. [Official TypeScript helper implementation](https://github.com/anthropics/anthropic-sdk-typescript/tree/590783078cd961a0df698d9fddc0275c65ff3afd/src/lib) · [Official Python helper implementation](https://github.com/anthropics/anthropic-sdk-python/tree/5139cf2e7d07aa618a6c30b7e0c712f10ccb5ad9/src/anthropic/lib)
- Claude Code routine fire (`POST /v1/claude_code/routines/{routine_id}/fire`) belongs to Claude Code's subscription product, uses a per-routine token, returns a newly created session on every successful call, and is absent from both Claude SDKs/spec. Document the scope boundary and link its HTTP instructions. Keep the Claude Code Admin analytics and Compliance transcript routes within the API inventory. Claude Agent SDK, first-party browser runtime, and CLI commands do not introduce direct Claude API routes. [Routine endpoint](https://platform.claude.com/docs/en/api/claude-code/routines-fire)
- Anthropic's `/v1/chat/completions` accepts the OpenAI request/response shape for interoperability. Document it as a separate integration using an OpenAI-shaped client; the native Dart Anthropic resource remains `/v1/messages`. Local repo OpenAI types/route already live in `openai_dart`; do not duplicate their implementations. [OpenAI compatibility](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)
