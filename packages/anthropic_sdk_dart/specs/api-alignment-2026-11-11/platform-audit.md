# Anthropic platform surface audit

Cutoff 2026-11-11. Dart baseline `acbd8c80ef6550e932319873b1778be2c575a0cd`, package 10.0.0, last spec promotion #302 (`7adfe29c`). Public source pins are [Python v2.8.0](https://github.com/anthropics/anthropic-sdk-python/tree/5139cf2e7d07aa618a6c30b7e0c712f10ccb5ad9) and [TypeScript sdk-v1.8.0](https://github.com/anthropics/anthropic-sdk-typescript/tree/590783078cd961a0df698d9fddc0275c65ff3afd). The identical SDK archives of the Anthropic OpenAPI document decode to SHA-256 `690622377a5eedc0e9f2265ed755ee34dc0c52d35b47327f425777a550f45e1e`. The archived spec has 385 method/path-selector pairs and 2,235 component schemas. The old pin had 214 and 1,229. Exact comparison yields 172 added and one removed operation, 1,011 added, 433 modified, and five removed component schemas. The pinned SDKs removed Text Completions. Its deprecated HTTP endpoint is still documented.

The spec's `?beta=true` path suffix distinguishes schema variants. SDKs use the shared wire path with the required feature header where one applies. Eleven categories of current endpoint already exist in Dart while Environments, Tunnels, Organization and Compliance need public resources. A limited-access beta can be implemented with documented fixtures and documented credentials even when a live account is unavailable.

## User Profiles

Dart exposes five legacy beta operations with `user-profiles-2026-08-18`. The snapshot adds six GA operations (create, list, retrieve, update, delete, action URL) and two additional legacy beta operations (delete and action URL). GA has a different response contract. Model `programs`, required-nullable `external_user_details`, enforcement status/action details, and the repeated `enforcement_status[]` list filter. GA create uses optional `name`, `access_type`, `external_user_details`, and `metadata`. The old top-level `external_id` and `external_user_onboarded_at` map to `external_user_details.reference_id` and `onboarded_at` in current requests. Keep callers using legacy enrollment URLs on the legacy contract with the beta pin. The GA action URL sends `{"action":{"type":"enroll_end_user"}}` and returns `user_profile_action_url`. The beta SDKs still inject `user-profiles-2026-08-18` on all beta methods, including delete and action URLs, although the latest snapshot no longer marks the header required at operation level. Preserve that pin on explicitly legacy Dart calls. Existing Dart user profile attribution on Messages, token counting, and Batches should continue to send `anthropic-user-profile-id`. ## Managed Agents

All six agent and 19 session operations already exist in Dart, including nested events, thread events and resources, and streaming. New contract includes `statuses[]` on thread lists; check current implementation against repeated serialization and paging. Agent create/update and agent/session responses gain `execution_identity` for service-account and AWS-role principals, including explicit null reset on update. Add multiagent v20261001 (workflows, subagents, advisors, predefined and inline agent variants), workflow-run phase/status/error events, and workflow linkage and refusal stop details on thread/session events. Permission policy gains `auto`; `agent.tool_use` and `agent.mcp_tool_use` gain typed evaluation with allow/ask/deny and reason codes. Add web fetch `url_sources` filters including shorthand inputs, and expanded session error branches for repository errors, tool use limit, and compaction limit. Preserve old v20260401 config, unknown event/permission values, and old fixture compatibility. Stream and list decoding must agree on event payloads. The reference and SDKs send `managed-agents-2026-04-01` despite missing operation-level beta markers on some snapshot entries. The release notes also describe server-enforced networking and web restrictions which merit examples/docs, with no client filtering. ## Environments and tunnels

## Files, Skills and Batches

Five Files endpoints are GA and already implemented, with binary download, multipart `file` and optional `expires_in_seconds`, cursor `page`/`next_page`, and repeated `ids[]`. The official beta variant accepts `scope_id`; Dart already exposes it on the shared Files resource. Keep compatibility and document its beta provenance. Eight Skills operations are GA, including cascade delete, plus the published beta namespace ZIP-download endpoint. Python and TypeScript now expose the latter under `beta.skills.versions` and do not pin a beta header there. Dart `downloadVersion` matches and needs its stale SDK claim corrected. No GA Files/Skills beta headers should be added by default. The old opt-in header retains the old wire shapes; distinguish shape compatibility from the current typed GA API.

All six Batch endpoints exist, with stable and beta selectors in the snapshot. Official SDKs implement results by retrieving the batch, requiring `results_url`, then streaming that URL as JSONL with `Accept: application/binary`. Dart currently calls the documented direct same-origin path and preserves request-ID metadata. Record the extra SDK preflight as a design choice or add checked opt-in following of same-origin result URLs while retaining the direct path. Apply the Messages version constraints to nested batch requests; verify beta headers, nested result branches, cancellation, malformed JSONL, and pagination with fixtures. ## Admin core and credentials

Dart has no Organization surface. The snapshot contains 234 organization method/path-selector pairs, 82 stable, corresponding to 152 unique wire operations. The full beta HTTP reference lists every one of the 152. The SDKs expose both stable and beta resource namespaces, often for the same operation with no beta gate. Implement shared Dart wire methods for aliases with matching contracts. Check Beta/GA schemas before equating them. Both SDKs omit 12 documented wire operations, namely nine deprecated tunnel operations and the three HTTP-only top-level reports below.

Core management includes current organization, API keys, invites, users, workspaces and nested members, org/workspace rate limits, and compliance settings (distinct from Compliance data). SDK v2 sends a Bearer key by default; the Admin guide explicitly documents `x-api-key` for admin keys and personal/service-account API keys, and Bearer OAuth for `org:admin`. Preserve both credential styles without sending two credentials. Confirm workspace ID filters and rate-limit query `group_type` remain unchanged even when response aliases are removed. Sign-out is Enterprise beta and requires `admin-user-sign-out-2026-10-08`.

Add federation issuers (5), rules including workspace binding (8), service accounts (8), workspace service-account membership (5), external encryption keys (6). WIF/service-account management operations require `org:admin` OAuth rather than an Admin API key. Cloud restrictions matter. Claude Platform on AWS supports workspace CRUD/archive, external key CRUD without validate, telemetry destinations, and dimensioned usage/cost analytics. See the Admin guide for console vs Enterprise availability and scopes. Test id filters, nullable state, archive behavior, and identifier escaping. ## Analytics, RBAC, spend and organization integrations

Analytics has 13 normalized routes, seven stable and six beta-selector-only. Two dimensioned `analytics/usage` and `analytics/cost` endpoints require `analytics-usage-cost-2026-08-24`. Four Enterprise `analytics/{usage_report,cost_report,user_usage_report,user_cost_report}` routes remain legacy. Three distinct HTTP-only reports also remain published (`/v1/organizations/usage_report/messages`, `/v1/organizations/usage_report/claude_code`, `/v1/organizations/cost_report`). Their spec keys use the beta selector, with no required feature beta header. The Claude Code usage report remains active. The Messages usage and cost reports are legacy. The report APIs have different cursor families and filters. Include parent organization filtering and Claude Tag metrics from current releases. Preserve old-version read aliases for `actor.email` and `summaries`; on 2026-10-21 use `actor.email_address` and `data`.

RBAC groups (8) and roles (3) GA responses use `role_ids`, `rbac_group_id`, and `display_name` in 2026-10-21. Group management/permissions are Enterprise. Effective spend limits and increase requests have GA shapes. Only GET list of spend limits explicitly pins `spend-limit-reads-2026-09-26`; the other spend operations must follow their own endpoint contract. API key responses use `scope` instead of `workspace_id`, including the Default Workspace's real ID and organization scope; rate limits use nested `group.type` instead of `group_type`. Avoid synthesizing the old ambiguous default workspace ID.

Plugins (13) and marketplaces (5) need `ce-plugins-2026-09-01`, scoped Enterprise admin credentials, and availability docs for HIPAA restrictions. Telemetry destinations (9) need `telemetry-destinations-2026-08-11`. Claude Tag (14) needs `experimental-claude-tag-2026-10-21`, Enterprise admin `read:claude_tag`/`write:claude_tag`, and support for Slack settings, effective settings sources, reply mode, and bundle targets. Organization webhooks (6) need `webhooks-2026-10-07` and requested beta access, with all three profile event types (enforcement opened/resolved and program status updated). Existing Managed Agents lifecycle webhooks are separately documented. Treat signature verification and OTel span emission as SDK helper capabilities; telemetry destination CRUD is an API surface. ## Compliance

The HTTP docs enumerate 39 operations absent from the official SDKs and their OpenAPI. Capture the official Markdown digest at cutoff and use the published wire contract. The Activity Feed has hundreds of event discriminators and must preserve future event/actor fields and unknown events losslessly. Activities, organization directory and settings/security posture, groups, app chats/files/projects/artifacts, and local/remote sessions need independent fixtures and clear scope docs. Stream or return bytes for the documented download routes and distinguish an empty body from JSON for deletes. Support bracket/dotted filter keys as documented, limit and cursor replay, including bounds for late-arriving activity data. Every request uses `x-api-key` and `anthropic-version`. A properly scoped Admin API key reaches only the Activity Feed. Other endpoints need a scoped Enterprise Compliance Access Key, with `read:compliance_user_data` for user content and `delete:compliance_user_data` for destructive operations. Standalone Console organizations can use only the feed. User preferences, security posture, and specific product surfaces are beta; documentation of a beta endpoint without a required beta header does not justify inventing a gate.
