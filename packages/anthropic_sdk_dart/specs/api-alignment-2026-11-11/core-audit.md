### API version and compatibility

- Current Dart sends `2023-06-01` unless overridden by `AnthropicConfig.apiVersion` or `defaultHeaders`. First-party SDKs now default to `2026-10-21`. Align Dart default with a major release and show explicit `apiVersion: '2023-06-01'` for callers who rely on legacy behavior. Document old Bedrock model restriction (only Claude 4.7 and later support the new version on Bedrock). Tests cover client constructors, environment constructor where feasible, configured header precedence including case, buffered, SSE, JSONL, and direct/multipart routes.
- `temperature`, `top_k`, and `top_p` produce HTTP 400 on the new version, including default-valued parameters. Retain deprecated Dart fields and their JSON representation for old-version callers. If guarding new-version calls locally, use the effective wire version and one boundary policy across create, createStream, and nested batch params. Never silently drop values. Explain removed sampling knobs versus task instructions/effort and do not claim effort is the equivalent sampling control.
- Direct assistant `document` blocks and non-empty citations in user `text` blocks (including `search_result.content`) are rejected on the new version. Keep legacy payload round-trips, document valid user document and citation-free user inputs, and test accepted assistant citations and empty user citations. Both official SDKs use role-specific typing but still serialize the same wire fields. Dart can keep `InputMessage` factories and validate version-dependent roles at request boundaries if needed. Distinguish current-model assistant-prefill restrictions from the API-version change.
- Old names in Admin and Analytics require explicit old-version decoding and new fields for new API consumers. `roles` → `role_ids`, `group_id` → `rbac_group_id`, `name` → `display_name`, `group_type` → `group.type`, `workspace_id` → scoped API key `scope`, `actor.email` → `email_address`, and `summaries` → `data`. Do not map legacy null API-key workspace ID to Default (it was ambiguous), and preserve old list filters still in use.
- Official SDK major releases send API keys as Bearer, use one credential, remove legacy Completions and client-side tool-runner compaction, remove beta argument from GA Models and convert single-value enums to constants, and adopt Apache 2.0. These are SDK changes. Claude accepts X-Api-Key and Bearer, so preserve existing ApiKeyProvider and add an explicit Bearer token provider if aligning authentication, with stable precedence and no duplicate auth headers. Dart exports legacy Completion models and has no Completions resource or old compaction runner. Preserve the models for existing callers. The HTTP endpoint is deprecated and remains documented. Keep the existing Dart license and wire-compatible enums. Validate fixed discriminators on new DTOs.

### Models, routing and ordinary Messages

- Dart accepts any model ID string, so Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.2 and eligibility-restricted Mythos 5.2 already fit the wire. Refresh examples and restrictions; Fable 5.2 requires new computer toolset except old tool on Bedrock and enforces thinking-prefix checks. Add missing typed `ThinkingConfig.betweenTools` to create/count/batch; docs distinguish model-dependent allowance, available effort, preserved thinking and account-bound signatures.
- Dart Models list and retrieve are implemented. Add model `line`, `lifecycle`, `deprecated_at`, `retires_at` and list `lifecycle[]` repeated values. Retain tolerant decoding for older responses, unknown forward values, and null; do not derive line from ID or retirement from clock time. Add `thinking.types.between_tools/disabled`, `capabilities.server_tools` and beta `capabilities.compaction.summarize`. The existing `code_execution` capability describes programmatic tool calls; distinguish from support for the server tool. Support Models beta call/header without sending the synthetic spec query. Exercise exact URL/headers and page cursor with all filters retained.
- Messages create/stream/count and Batches create already accept user-profile attribution; Dart default headers can route workspaces, but typed per-request `anthropic-workspace-id` is missing. Audit pinned endpoint header support before adding arguments and keep auth/default/header precedence. All GA/Beta Messages and Batches HTTP operations exist in Dart unified resources except per-call beta on Batches. Add per-call beta/header/cursor behavior for the same path where the SDK does, including streamed batch results. Also review Files/Skills and Managed Agents workspace selectors.
- Request size increase 32 MB → 128 MB on the first-party API is documentation only unless a Dart-side size check exists. Opus 5.5/Fable 5.2 fast mode no longer needs a beta header; older preview models may still require it, and Opus 4.8 fast mode is scheduled to retire November 30. Dart already models request/count/usage speed. Cache diagnostics GA already has Dart request/response fields and stream accumulator wiring; update beta docs and test detailed request/response paths.

### Threads, compaction, and streaming

- Messages threads are absent (existing Managed Agents session threads are unrelated). Model `thread: {type: create}` and `thread: {type: continue, previous_message_id: ...}` on create and SSE; beta `message-threads-2026-08-12` on all turns. Continue sends new messages only, without system/tools. Update cursor from completed response ID; stream cursor cannot be reused before `message_stop`. Pause-turn continuation can use empty messages; unsupported combinations include on-demand compaction and token counting of held state. Typed SDK helper has history, replay-on-404 once, reset/fork, stream completion, and refusal/fallback behaviors. Preserve explicit manual operation independently of optional helper. Test exact create/continue wire bodies, premature/canceled stream, resumed pause, full-history replay with cache breakpoints omitted as required, and no automatic replay on other failures.
- Existing auto-compaction blocks handle text/encrypted content, but signed on-demand compaction lacks `compaction: {type: summarize, instructions?}` and request/response `signature`, `tool_changes`. Keep absent/null/empty distinction where significant. Add signed block to response→input conversion and SSE accumulation. The documented on-demand stream sends a complete signed block in `content_block_start` with no delta, so the reducer must preserve the start block’s signature and tool changes. For legacy auto-compaction, official reducers treat `compaction_delta.content` as replacement (including explicit null) and copy `encrypted_content`; Dart currently appends content and never reads encrypted delta metadata. Test both modes and resending the exact emitted signed block. Gated by `compact-2026-09-04` on the summary and follow-up requests, excludes `context_management` on same request, and needs beta Models capability. Verify token counting shape against pinned type. Keep original auto-compaction compatible.
- `input_transformations` already parsed in message and deltas, but only typed `thinking_dropped`. Add `thinking_mismatch_allowed` with path and reason, retain raw unknown enum/union values, and test streaming merge. Preserve signature verbatim across assistant history; document release notes' prefix and account rules, no client-side rewriting.
- Baseline SSE accumulator already offers text/thinking/tool JSON/citations/usage aggregation, but ignores ErrorEvent, can expose partial message as completed, and has older helper gaps. Add explicit final/partial completion semantics, chunk/index checks, and carry new compaction/tool deltas to round-trip. Unknown events allowed by provider versioning; keep stream handling forward-compatible while distinguishing malformed known events.

### Tools, errors, and SDK conveniences

- Toolset declaration, generic tool-use input maps, browser state inputs, and mid-conversation add/remove references exist. Type pinned browser/computer member calls by `toolset_name` and `name` within the stable `tool_use` discriminator (31 browser and 17 computer member types, with shared GA/Beta shape and generic custom fallback). Verify single action/member fields, multiline streamed JSON, no GA beta header, older tool gate, paired result shapes, and raw unknown members. SDK driver helpers add command dispatch, tool loop, approval and URL/file policies; audit independently of the wire ticket. No default browser/desktop automation driver is necessary to send requests.
- Inline tool changes lack `tool: {type: tool_definition, definition: ...}` and response/request `mcp_tool_listing` pinning. Add typed request and response block pairs, SSE/replay wiring, distinct server/client/MCP definitions, `inline-tools-2026-09-15` / `mcp-client-2026-09-15` as documented, and test simultaneous header gates without dropping caller extras. Check older web fetch `url_sources` and `content_too_large` error against Dart. Preserve round-trippable unknown enums and remove no public experimental values solely because GA shape changes.
- Dart HTTP status exceptions retain request ID (including #445/#447) and existing auth/rate-limit/validation subclasses. API error body may also carry top-level `request_id`. Dart currently stores only error type in a historical `details: List<Object>`, losing structured `error.details.error_code`, `error.details`, and original type/message distinction. Add structured fields/accessors preserving legacy details and exception catch behavior, unknown codes, malformed bodies and HTTP error subclasses as needed. Normalize header request ID, use body fallback where supported, never surface client correlation ID as provider ID. Midstream `ErrorEvent` currently loses SSE response request ID and parsed details. Official SDKs terminate with error carrying original headers; preserve Dart low-level event surface with explicit terminal semantics and add exception behavior to the final-message convenience. Exercise normal JSON, streaming pre-HTTP and in-band errors, batch per-item error versus HTTP response, direct file/skill paths, retry headers, redaction and cancellation.
- Older official SDK ergonomics: typed structured-output parsing (including schemas containing `const`/`enum`), strict tool input, tool runners (sync/stream, mutation, limits, error results, on-demand compaction), first-class stream lenses and final reply, typed cursor auto-paging, MCP tool/prompt/resource adapters, raw/streaming response wrappers, OpenTelemetry and credential integration. Baseline Dart supports schema JSON, manually executed tools, stream accumulator, cursor DTOs, server-side MCP connector and HTTP injection. Record implementation versus Dart-native equivalence vs third-party adapter/platform-specific work; do not mark wire coverage as full helper parity. Session tool runner is separate Managed Agents work. Retry behavior must remain request-scoped and abortable.
