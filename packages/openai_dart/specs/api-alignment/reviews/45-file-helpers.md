## Explicit selection, partial ownership and privacy

`AgentFileInput.bytes` snapshots exact bytes; `.stream` captures a lazy factory and declared length. Both require an explicit filename and hosted destination. Validate every selection, ancestor/duplicate conflict, filename, declared size and shared default/request idempotency key before any source opens or HTTP sends. Helper paths deliberately reject dot/empty/backslash/NUL and reserved workspace roots; this does not silently tighten raw canonical path DTOs.

`AgentFiles(client)` captures matching resource generations. `prepare` materializes and uploads one file at a time with purpose=user_data, in order. The default64MiB configurable per-file budget is local memory policy, not an API quota or constant-memory upload claim. Length mismatches, invalid bytes and source failures stop before their upload. Stream factories and arbitrary application callback work remain caller-owned.

Actual successful upload IDs are recorded before hosted-reference construction or cancellation checks. `PreparedAgentFiles` and private `AgentFilePreparationException.prepared` retain detached observed IDs/usable references after failure. Uncertain delivery never fabricates an ID. `stage` separately copies one upload into an existing connected environment and retains the upload if staging fails. It omits inherited/default/shared upload idempotency keys for that distinct write. A final helper-only interceptor rejects repeated dynamically supplied keys before the affected upload; it does not pre-resolve credentials, mutate client middleware or alter ordinary raw Files behavior. Unique/single-upload keys remain supported.

Cancellation scopes use one lightweight caller-future continuation per phase and removable per-file callbacks. Each native HTTP request gets a separately disposed signal, so completed buffers/requests are not retained on one never-completing shared abort future. Startup abort, abort between upload/staging and late source/sink failures are observed. No remote deletion, environment creation, directory synchronization or inferred cleanup occurs.

Request-scoped `redactDiagnostics` defaults false and never adds a wire marker. Explicit private uploads keep package logger URLs, headers, body/error/correlation text private before middleware/transport failures escape. Existing HTTP exception identities/classes, exact body fields and explicit causes remain accessible; a weak internal label changes only automatic diagnostics. Native network failures retain retry eligibility, while arbitrary/provider-origin failures do not become replayable. Safe `VertexAuthenticationException` identity remains intact. Ordinary default-false raw requests preserve their behavior. Application-controlled middleware can explicitly inspect/log its own values; the guarantee concerns package diagnostics.

## Completed result identity and exact binary downloads

`AgentResultArtifacts(client: client, result: completedResult)` snapshots the actual completed root turn from `AgentSessionRunResult` or its parsed subclass and captures the resource generation. It does not accept guessed session/turn IDs, perform another result observation or infer success from HTTP202. Session and selected artifact routing IDs must survive URI encoding losslessly; valid opaque Unicode remains unchanged. The same tiny guard completes existing streamed-creation admission before local handlers can execute against a normalized different session ID.

`find` compares exact session/selected-turn/hosted-path across every page, without environment filters. Expired hosted environments do not affect immutable published artifacts. Empty pages may advance using the actual last_id. Missing/empty/repeated/cyclic cursors fail; row IDs, first_id, paths or future file_id fields are never substituted. This is deliberately stricter than Node's row-ID fallback/first-match conveniences. Zero/multiple exact matches fail, including matching legacy rows without IDs; a unique selected legacy row with no usable identifier fails privately.

`downloadTo` reuses the existing binary content route and an explicit awaited chunk callback. Chunks are detached, read-only and preserve non-UTF8 bytes. Sink callbacks run sequentially with backpressure; underlying transports/adapters may buffer/prefetch. Abort/sink failure ends local observation promptly and cancels upstream best effort without waiting for hostile cancellation or a never-completing sink. Late callback failures are observed. The caller owns sink flush/close. Hosted paths never choose local output destinations, and no artifact is deleted.

## Optional IO and overwrite choice

Only `openai_dart_agent_files_io.dart` imports the filesystem adapter; the main library remains usable in Chrome/Wasm. `AgentFileSystem.open` requires an existing application-owned root. `selectFile(relative,destination:hosted)` selects one regular source lazily. `downloadFile(artifacts,path:hosted,destination:relativeLocal)` requires an explicit independent local destination and existing parents.

Dart deliberately uses **no overwrite**: existing files, directories, symlinks and dangling links reject unchanged before HTTP. Creation is exclusive, followed by a nontruncating held write handle. No implicit directory creation, synchronization or automatic deletion occurs, even after partial failure/path replacement. Pending writes settle before handle close. Symlink/nonregular types and invalid/colon-bearing components reject; lossless Unicode validation precedes filesystem effects.

Canonical paths, size, mode, change/modify times and held-handle lengths detect ordinary replacement/size changes. Public Dart IO has no descriptor inode/device stat or atomic no-follow/open-at API, so checks cannot prove identity against same-metadata swaps or hostile concurrent ancestor replacement. Exclusive creation and opening are separate. Stable application-owned directories are an operational requirement, not a sandbox. Node's native no-follow/inode guards and verified overwrite policy are not claimed; Python delegates destination streaming. Host VM fixtures do not claim Windows runtime verification.
