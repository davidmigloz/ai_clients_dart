## Retained compatibility and known backend scopes

- Developer model calls can opt into v1 independently. Existing beta callers keep explicit `include_input`, the beta revision header and SSE compatibility query where applicable, stored interaction history, and the legacy response modality and MIME options. Standard v1 output should be read from typed steps. Upstream convenience accessors for `output_*` are computed from steps and do not imply restored top-level REST fields. Superseded content events and turn schema rows correspond to the existing steps migration. [Developer migration](https://aistudio.google.com/docs/migrate-to-interactions) · [May steps migration](https://aistudio.google.com/docs/interactions-breaking-changes-may-2026)
- Retained Dart symbols for legacy CodeMender/session and local environment inputs, old Deep Research BigQuery configuration, video `gcs_uri`, model-output `error` and older thresholds remain compatibility options. Their absence from the current Developer schema does not establish availability. Legacy retrieval, ranking, filters and partner/Vertex search symbols remain useful to Cloud/custom gateways where their own contract permits. Developer `tool_search` does not turn those older retrieval types into supported Developer features.
- Agent list/create retain optional `parent` for released Developer SDK behavior. Trigger creation and updates retain the released SDK's flat bodies. An explicit trigger update mask selects the reference envelope. Run resolves the ID from the route. Webhook update keeps the SDK's flat body and query mask although the frozen OpenAPI shows an envelope. Ping and rotate preserve released SDK body semantics. The candidate's placeholder-only aliases do not create new public routes. [Pinned JS SDK](https://github.com/googleapis/js-genai/tree/719dffc91dbf38f8a5f2d90bf93efa5dc8207999/src/gaos) · [Pinned Python SDK](https://github.com/googleapis/python-genai/tree/aa813f8bf805b6f4f3e57abb8f04b91d769e23e6/google/genai/_gaos)
- Developer managed services, tool retrieval, Decisions, Voices and paid Genie use their documented beta surface. Vertex Interactions uses OAuth and distinct Cloud operations. Cloud managed Antigravity requires its documented global v1beta1 route and tool limits. The dedicated `vertex_ai` package stays outside this alignment. [Developer version matrix](https://aistudio.google.com/api-reference/api-versions) · [Cloud managed agents](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/managed-agents/interact-with-agents)
- Environments browser downloads require an endpoint that returns bytes directly because Fetch does not expose manually followed signed redirects. Native redirects use a credential-free transfer. The Dart upload method follows the SDK's resumable protocol. The separately documented direct one-PUT REST form on `/upload/` is not exposed as a Dart mode. [Workspace files guide](https://aistudio.google.com/docs/agent-environment#download-files-from-the-environment)
- Model availability varies by backend. Developer Veo 3.1 Preview IDs retired in October. Developer clip-based video uses Gemini Omni. Vertex GA Veo uses its project/region prediction route. WebRTC and WebSocket Genie are distinct from ordinary Live. [Video model guidance](https://aistudio.google.com/docs/video) · [Genie transport guide](https://aistudio.google.com/docs/genie)
